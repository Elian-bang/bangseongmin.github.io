## See you later

---

이번 주에는 필자가 작업하던 프론트 부분이 완성되었다... 

완성이라고 하기에는 몇가지 남은 기능이 있지만 해당 부분의 기능이 배포되었다... !!!

![본문 이미지](../assets/tistory/a2575897aa3c9df005206a97.gif)

### Vuex

Tooltip이라는 기능을 상태관리하기 위해서 Vuex를 사용해야 했다...

그런데 Vuex가 무엇이지? 하면서 Vuex까지 공부하려고 하는데 Vuex는 현재 공부하는 부분에서 한참 떨어져있다.. 

간단하게 유튜브를 통해 경험하였지만... 이해하기 쉽지 않았다.. 어떻게 관리되는 거지?? 언제 사라지지 이러한 고민을 하다가 시간이 많이 날아갔다.... 중요한 것은 구현을 하는 것이고 구현하고 나서 공부해도 늦지 않을 것이라 판단되어... 먼저 구현을 하게 되었다...

> 생각은 시간만 늦출 뿐...  
>   
> 구현하면서 배우는 것이 더 많다.

### Stag and Feature

필자는 Stage에서 Feature 브랜치를 생성하여 본인의 작업을 진행하여 개발해본 경험이 있다. 

사이드 프로젝트를 진행할 경우 겹치는 경우가 적었다.. 기능이 분리되어 있기 때문에 그런한 일이 거의 없었다...

그런데 해당 기능을 구현하면서 프론트 부분에 작업하는 분이 본인 포함 3 명이었기 때문에 겹치는 코드가 계속 발생하였다... 그래서 아무 생각 없이 평소 처럼 Stage를 최신화하고 Feature를 Stage에 Merge를 했었는데 이때 큰 문제가 발생하였다.. 기존에 작업한 다른 분의 코드를 다시 필자가 덮어쓰게 만들어 다른 분들의 코드가 되돌려지게 된 것이다...

이러한 작업이 진행되었는지 필자는 파악하지 못하고 있다가 Stage 배포 후에 알게 되었다.... 

문제가 없을 때도 있지만... 습관이 무서운 것 같다.... 습관을 들여서 다른 사람들에게 피해가 가지 않도록 노력하자!!

> 습관의 중요성...  
>   
> 최신화하여 현재 작업된 파일을 동일하게 작업한 분이 있는지 파악하지 않아도 된다.  
>   
> 1. Update Stage  
> 2. Merge Stage -> Feature   
> 3. Merge Feture -> Stage  
> 4. Push Stage

### 집중력의 부재...

Tooltip을 Stage에 저장하는 기능을 완성하였는데.. 구현되지 않았다고 계속해서 피드백을 받았다... 

State를 초기화하여 계속 작업을 하였는데 정상 작동되었다...

그런데 해당 페이지에 다른 기능에서 해당 Tooltip에 대한 값을 변경해주는 부분이 있었다..

성공하는 사례만 생각하고 개발하다 보니 이러한 문제가 발생했던 것 같았다... 

![본문 이미지](../assets/tistory/db033815451e7e78fe33afff.gif)

그런데... 또 해당 기능에 문제가 있다고 말씀해주셨다...

Stage 서버에서 테스트하고 또 확인하고 다른 계정을 생성하여 테스트하고 반복했다.. 문제가 될 수 있는 코드를 삭제하고 더 간결하게 코드를 만들었다. 문제가 발생할 수 있는 상황을 최대한 줄이기 위해서 였다....

그런데 문제는 그것이 아니였다... 피그마를 신경써서 보지 않았던 필자의 문제였다... 

해당 Tooltip에 State가 변경되는 조건이 2개가 아니라 3가지였다.... 간단하게 보고 넘기다 보니 발생한 문제였다...

> 사소한 것 하나부터 시작이다...  
>   
> 신경쓰지 않아야 할 것이 없다...  
>   
> 모든 것을 생각하고 하나씩 차근차근 접근하여 해결하면 된다.

### Pop Pop Pop...

필자는 개발하다가 이전에 작업한 기능에 문제가 있다는 이야기를 들을 때 Stage에 기존 작업을 저장해둔다

Commit을 해두어도 되지만 Stage에 저장하는 것이 편하기 때문에 Stage에 저장해두고 개발한다.

Stage에 저장하면 해당 기능을 구현하는 다양한 방법을 적용하여 효율적인 코드를 선택할 수 있기 때문에 더 Stage에 저장하는 방법을 사용한다.

CLI를 통해 Stage에 있는 내용을 Pop하다가 렉이 걸렸는지.. 

Stage pop을 2번 발생시켜버렸다.... 이전에 작업한 내용이 사라지고 전전에 작업한 내용이 반영되어 버렸다...

그래서 필자가 작업한 3시간에 코드가 사라져버렸다.......

![본문 이미지](../assets/tistory/9ded92f571a9601367ec1c40.gif)

코드가 더러워서 다시 작업하려고 했었지만... 어떻게 작업했는지 확인할 수 없었다... 해당 기능을 구현한 코드는 Pop으로 날아가버린 코드밖에 없었기 때문이다...  신경쓰지 않고 다시 집중해서 해당 기능을 구현하고 있는데 이전보다 코드가 깔끔해진 것 같아서 좋았다...

이전 코드를 계속 생각하려하는 것이 오히려 더 많은 시간을 소비하게 되었다...
